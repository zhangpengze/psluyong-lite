================================================

--------

0. 出厂包先建 .env（只有 --no-env 的包需要）
------------------------------------------------
cp .env.example .env    （文件管理里复制并重命名即可，注意别存成 .env.txt）
必填三项：SECRET_KEY / API_KEY / ADMIN_PASSWORD
    python -c "import secrets;print(secrets.token_urlsafe(48))"   # 生成 SECRET_KEY
    python -c "import secrets;print(secrets.token_urlsafe(32))"   # 生成 API_KEY
要接日报推送再填：NAPCAT_TOKEN / REPORT_GROUP_ID
不建 .env 就启动会报「env file .env not found」或「环境变量 SECRET_KEY 未设置」——
这是预期行为，先把 .env 建好。

一、上传解压
------------
1. UGOS「文件管理」→ docker 共享文件夹 → 新建目录 psluyong-lite
2. 上传本 zip（**单个文件上传，不要用上传文件夹**）
3. 右键 zip → 解压到当前目录
4. 解压后必须满足：
   - docker/psluyong-lite/ 第一层直接看到 docker-compose.yml、Dockerfile
   - 第一层有 server/ bot/ core/ data/ 四个文件夹
   - 没有 psluyong-lite/psluyong-lite-nas/... 这种多套一层
5. 文件管理右上角勾选「显示隐藏文件」，确认 .env（出厂包为 .env.example）
   和 .dockerignore 在

二、建项目
----------
UGOS「Docker」→「项目」→「创建」
  项目名称   psluyong-lite
  项目目录   docker/psluyong-lite
  编排文件   docker-compose.yml
创建后启动。首次构建 2~5 分钟。

注意：如果界面让你填「Dockerfile」内容，那这里要填 Dockerfile 文件的内容，
不要填 compose 的 YAML。两者填反会报
  dockerfile parse error on line 1: unknown instruction: ...

三、验证
--------
http://NAS的IP:8080/health/ready     返回 ok
http://NAS的IP:8080/                 账号 admin，密码见 .env 的 ADMIN_PASSWORD
                                   （首次登录后请立刻改掉）

四、验收日报推送
----------------
后台「每日日报」→ 选一天 → 「重推此日报」→ QQ 群 134132323 收到消息

五、构建日志怎么看好坏
----------------------
=> => transferring context: 几十~200kB   ✓ 文件传全了
=> => transferring context: 3.32kB       ✗ server/bot/core 没上传
=> [4/8] RUN pip install ...             ✓ 走清华源，1~2 分钟
下载速度只有十几 kB/s 或 read timed out  ✗ Dockerfile 里残留了 pypi.org 源

六、失败对照
------------
容器一直「重启中」+ 日志 PermissionError: '/app/data/images'
    → 挂载目录属主 / ACL 问题。本包 compose 已带 user: "0:0" 与启动前
      chmod -R 777 /app/data，正常不会再出现。
      若仍出现：文件管理里把 data 目录权限改成所有人读写；再不行就把
      volumes 换成命名卷 psluyong_data:/app/data（会牺牲现有数据）。

dockerfile parse error / unknown instruction
    → Dockerfile 里装的是 compose 内容，两个文件搞反了

COPY server ... not found
    → 构建上下文只有 3.32kB，源码目录没上传全

env file .env not found / SECRET_KEY 未设置
    → .env 没上传，或存成了 .env.txt（Windows 隐藏扩展名的坑）

推送 401/403
    → .env 的 NAPCAT_TOKEN 与 NapCat「网络配置 → HTTP 服务端」Token 不一致

推送「连不上」
    → 把 .env 的 NAPCAT_WEBHOOK 改成 http://NAS的局域网IP:13000，重启项目

群不存在 / 无权限
    → 扫码登录的 QQ 不在 134132323 群里，或群号写错

七、这台机器是 ARM64
--------------------
日志里 wheel 名带 aarch64。以后拉镜像要选有 ARM 版本的，
否则报 exec format error。python:3.11-slim 与 napcat-docker 都支持。

八、备份与安全
--------------
备份只需备份 data/ 目录。
8080 是管理后台，不要直接暴露公网，只在内网用或前面挂 HTTPS 反代。
数据回滚：docker exec <容器名> python -m server.backup --list 找备份，
--restore <文件> --rehearse 先彩排，通过后 --restore <文件> 真恢复，
然后重启项目。完整步骤见 docs/DEPLOY.md 第五节「回滚」。

九、给开发者（这个 zip 是怎么来的）
----------------------------------
deploy/nas/ 目录本身没有 Dockerfile 和源码，在那里直接 docker compose up --build
会失败——必须在仓库根先打包，zip 解压后才是完整构建上下文：
    python scripts/package_nas.py              # 含 .env 的安装包（带密钥，敏感件，勿外发）
    python scripts/package_nas.py --no-env     # 出厂包，不含任何密钥
    python scripts/package_nas.py --no-data    # 空库部署
打 tag / 回滚见 docs/DEPLOY.md 第五节，配置差异对照见第六节。
