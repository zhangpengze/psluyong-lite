# 计划书 → 落地实现：决策与差异

记录这份实现相对《PS模板批量生成与工作日志管理系统》项目计划书做了哪些调整，以及为什么。

## 四个前置决策

| 决策点 | 选择 | 原因 |
|---|---|---|
| 交付方式 | 新建独立仓库 `psluyong-lite` | 原 `psluyong` 已累积账务、公告、双客户端等与本项目无关的部分，在它上面做减法容易漏 |
| 技术栈 | **Flask + SQLite**（不用 FastAPI + MySQL） | 单机/小团队量级 SQLite 够用；Flask 的会话、模板渲染现成；省掉 MySQL 的运维和部分索引迁移坑 |
| 账务 | **砍掉**（金额/收款方式/余额/期刊） | 计划书定位是"工作日志"，账务是原项目额外长出来的需求 |
| 客户端 | **Tauri 2 + Vue 3**（不用 PySide6） | PS 只需要一个能调 COM 的进程；界面用 Web 技术做更快更好看，打包体积也小 |

## 相对计划书的调整

| 计划书原文 | 实现 | 理由 |
|---|---|---|
| 主管后台用 FastAPI + Jinja2 | Flask + Jinja2 | 与后端同一套框架，少一个服务 |
| 客户端 PySide6 | Tauri 2 + Vue 3 + Python sidecar | 见上；Python 只负责 PS，不碰 UI |
| 数据库 MySQL 8 | SQLite | 单文件、零运维、备份=复制目录 |
| 「替换1 / 替换2」 | 业务语义化为「作者 / 标题」 | 员工看得懂；占位符仍可自定义（存在模板上） |
| 日志字段 `replacement_1/2` | `author` / `title` + `warnings` | 去掉冗余，补上生成告警（字体缺失、文本溢出） |
| 图片按 `年/月/日/员工/` 分层 | 按 `年/月/日/` 分层 + UUID 文件名 | 员工名可能改；UUID 防重名。筛选靠数据库，不靠目录结构 |
| QQ 机器人用 iframe 嵌 WebUI 扫码 | 后端 APScheduler 推送到 NapCat HTTP 接口 | iframe 嵌第三方 WebUI 在 NAS 反代下坑多；推送接口更稳 |
| 全文检索用 `LIKE` | 保留 `LIKE`（作者/标题/合作伙伴/模板/员工） | 与计划书一致；万条以上再上 Meilisearch |
| PoC 用真实 PSD 验证 | 引擎层已就绪，**PoC 仍需你在真机跑一次** | 见下方"待你确认" |

## 计划书里已实现的部分

- ✅ 员工客户端：模板选择、合作伙伴、两组文字、一键生成、缩略图、打开文件夹
- ✅ 多分辨率/缩放：Tauri 用 WebView2，跟随系统 DPI，无需额外适配
- ✅ PS 文字替换与导出：COM + 占位符精确匹配（复用原项目加固过的引擎）
- ✅ 日志入库：员工/日期/模板/合作伙伴/作者/标题/图片/机器名/PS 版本/状态/耗时
- ✅ 图片本地存储：不经过任何云服务
- ✅ 主管后台：登录、记录列表、日期+员工+合作伙伴+状态筛选、关键词搜索、缩略图点开原图
- ✅ 每日汇总：今日总量、成功率、按员工/模板/合作伙伴分布、近 7 天趋势
- ✅ QQ 群日报：定时生成 Markdown 并推送（未配置时只存档不报错）
- ✅ 离线能力：断网时记录落本地队列，下次生成自动补传
- ✅ 部署：Dockerfile + docker-compose，数据全在挂载目录

## 待你确认的三件事

1. **PS 版本与占位符**：你们实际用的 PS 是哪个版本？模板里的两处文字现在是怎么写的（图层名固定？还是已经有 `{{}}` 之类的标记）？这决定要不要做图层名匹配的降级路径。
2. **要不要账务**：现在是彻底没有金额字段。如果主管其实要看"每天录了多少篇、对应多少钱"，得把 `amount` 加回来（改动量约半天）。
3. **QQ 机器人现状**：NAS 上是否已有 NapCat / AstrBot 在跑？有的话我按它的接口对齐；没有的话给一份从零部署的步骤。

## 与原项目的差异一览

| 维度 | psluyong（半成品） | psluyong-lite（本仓库） |
|---|---|---|
| 代码量 | ~63k 行 | ~4.5k 行 |
| 客户端 | PyQt5 迷你窗 + Tauri 2 两套 | 只有 Tauri 2 |
| 数据模型 | 含账务、幂等回执、乐观锁 | 4 张表，无账务 |
| 后台 | Vue 3 SPA（11 个页面） | Jinja2 服务端渲染（5 个页面） |
| 测试 | 74 个文件 | 25 个用例（39 项断言） |
| 启动依赖 | MySQL/SQLite、多容器 | 单进程 + SQLite |
