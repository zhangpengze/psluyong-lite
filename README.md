# 期刊录用管理系统（精简版）

PS 模板批量生成 + 工作日志汇总。员工在任意 Windows 上填两组文字一键生成，
记录与成品图落到 NAS，主管用浏览器看板检索汇总，每天定时把日报推到 QQ 群。

> 从 `E:/psluyong` 的做法里提炼而来：保留跑通过的 PS COM 引擎与加固逻辑，
> 去掉账务（金额/收款方式/余额）等与本项目无关的部分。

## 快速开始

### 1. 起后端

```bash
cp .env.example .env          # 填 SECRET_KEY / API_KEY / ADMIN_PASSWORD
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt
.venv/Scripts/python.exe -m server.run
```

打开 http://127.0.0.1:8080 ，用 `ADMIN_USERNAME` / `ADMIN_PASSWORD` 登录。

首次进入请依次：
1. 把 `API_KEY` 发给员工
2. 员工在自己客户端里上传 PSD 模板、维护合作伙伴名单（模板与字典都不在后台维护）

后台四个页面：

- **数据概览** — 合作伙伴视角的数据面板：KPI 行（合作伙伴/模板调用/成功率/活跃员工，
  各带环比参照）、调用趋势图、合作伙伴调用 TOP5、合作伙伴明细表（点行展开看每个
  模板用了几次，可下钻到该伙伴的全部记录）；时间范围五档（今天/昨天/近7天/近30天/
  自定义），30 秒自动轮询 + 手动刷新；底部一张「系统状态」卡：后台服务 / 数据库 /
  数据库备份 / 日报推送 / 图片存储五个组件行，各带状态点（绿/琥珀/红/灰）
  与真实指标（备份时间、磁盘占用与阈值等）——没有可探测的延迟就不编毫秒数
- **录用记录** — 日期区间 + 员工/合作伙伴/状态 + 关键词筛选、点行展开完整详情
  （含告警与错误原因）、缩略图灯箱、按当前筛选导出 CSV、下方折叠的回收站可一键恢复
- **每日日报** — 历史日报列表（带已推送/未推送徽标）、正文预览、一键重推
- **操作日志** — 删除、恢复、导出、重推、登录与登录失败的审计流水

全局：亮/暗双主题（默认跟随系统，可手动锁定）、全键盘可达（Tab / 回车展开详情 /
Esc 关闭弹窗）、自定义确认弹窗替代原生 `confirm`、所有异步操作有 loading 与 toast 反馈。

### 2. 起客户端（开发）

```bash
cd client
npm install
npm run tauri:dev
```

设置页填：姓名、服务器地址、API Key，并上传 PSD 模板（可一次选多个，中文名保留）。
合作伙伴名单也在设置页，一行一个。然后回「录用」页选模板、填作者/标题、点生成。

客户端界面（三个独立窗口，玻璃质感按精简版收敛）：

- 亮/暗双主题：主窗头部一键切换，偏好随配置走，换机器不丢
- **主窗 360×222（高度随内容自适应）**：选模板 → 填作者/标题 → 点生成，一屏一个动作。
  窗口高度由内容决定（量一次内在高度再让 Rust 改窗口），常态 222px、
  出现配置提示或结果条时长到 280~310px，绝不靠"居中"把空白摊到上下；
  草稿自动保存（中途关软件能接着填）、
  生成进度并入主按钮、结果条显示文件名/同步状态/打开文件夹/复制路径、
  `Ctrl+Enter` 提交、`Esc` 隐藏窗口、置顶与贴边按钮；
  主题在头部一键切换（半黑半白的圆 = 明暗），设置里不再放第二份；
  贴边**不用选方向**：把主窗拖到任一屏缘 24px 内松手就贴到那一缘，或者直接点贴边按钮——
  贴哪边由窗口离哪条边近决定（QQ 自动隐藏的用法），鼠标碰到露出的 6px 窄条即滑出；
  等超过 90 秒主按钮自动变「取消生成」——PS 卡在对话框上时员工有脱身办法
- **记录窗 840×640**：今天 / 近 7 天 / 近 30 天 / 全部 四档区间，旁边两个日期框可以直接
  选起止日（只填一头也能用：只填起始＝到今天，只填结束＝就看那天）；**点任意日期分组标题
  就是「只看这天」，再点一次取消**；搜索 + 模板/合作伙伴/状态三个筛选挤在工具栏里，
  表头只画一次并吸顶，一屏能看 10 行；**时间和日期分组都带年份**（`2026-10-24 01:04`、
  `今天 · 2026年10月24日 周六`），跨年不会认错批次；
  作者 / 模板 / 合作伙伴三列随窗口宽度依次让位，标题始终保留；
  缩略图点开灯箱看大图，文件名一键复制（行悬停显形）、直接打开输出文件夹
- **设置窗 640×540**：账号 / 模板 / 生成 / 窗口 / 高级 五个标签，每组都能一屏放下，
  不用滚；保存栏只在有未保存改动时出现，配置缺项时直接落在缺的那一组；
  「窗口」组只剩主窗行为（置顶/自动贴边/关闭去向）——主题搬到主窗头部了；
  贴边**没有方向选项**——那是运行时该决定的事，不占用员工的选择（设置里只留
  「拖到边缘自动贴边」的总开关）
- 录用页记忆：上次用的模板/合作伙伴/作者自动带出，草稿自动保存
- 全局：toast 通知、确认弹窗（替代原生 alert/confirm）、首启引导横幅、
  服务器恢复后自动补传离线队列，离线/待补传才在底栏出声

## 生成链路

```
员工点「生成图片」
   → sidecar 校验参数（模板是本机上传的 PSD，不联网）
   → PS：导出前体检（读真实尺寸当基准、CMYK→RGB、16bit→8bit）→ 打开 → 递归遍历文本图层 → 精确替换两个占位符
   → 导出到临时名 X.psluyong-tmp.jpg（COM 返回成功 ≠ 文件存在）
   → 金标准校验：能否解码 / 尺寸对模板 / 是不是几乎纯色 → 通过才 rename 成交付名
   → multipart 上报记录 + 成品图
   → 上报失败则进本地队列，下次生成时自动补传
```

生成日志字段（已去掉账务）：

`work_date`、`employee_name`、`template_name`、`partner_name`、`author`、`title`、
`image_path`、`client_machine`、`ps_version`、`status`、`error_message`、`warnings`、`processing_ms`

## 关键设计

| 问题 | 做法 | 原因 |
|---|---|---|
| PS 报错员工看不懂 | HRESULT 表 + 关键字规则翻译成中文动作 | 员工不需要知道 0x800706BA 是什么 |
| COM 返回成功但没生成 | 先导出到 `X.psluyong-tmp.jpg`，再用 Pillow 校验（大小下限/能否解码/尺寸对模板/不是纯色），通过才 rename 成交付名 | 假成功比失败更坑。原来只验「存在 + 大小 > 0」，1×1 图、全白图、SaveAs 被杀出来的半截文件全都能过；半截文件还顶着完全合规的文件名，交付时按名字拿错 |
| 导出的图"看着像但不对" | 有证据价值的（尺寸不符/几乎纯色/色域可疑）另存 `X.校验未通过.jpg` 保留，没证据价值的（<2KB/解码失败）直接删 | 全白图得让人能打开核对是模板问题还是渲染问题；垃圾字节留着只会占地方还让人以为是好的 |
| 没有图层被替换 | 零匹配直接判失败 | 否则导出一张跟模板一样的图，员工以为做完了 |
| 同一天重复提交 | 部分唯一索引 `(work_date, employee_name, template_name, author, title) where is_deleted=0` | 路由层"先查后插"挡不住并发；键里带员工与模板，两个人做同一篇稿、或同一个人出两个期刊模板都不会互相挡 |
| 断网怎么办 | 记录先落本地队列，下次自动补传 | 不能让员工白干 |
| PS 卡住不动了 | 等 90 秒主按钮变「取消生成」，杀掉 worker 子进程并落一个确定的 cancelled 终态 | 原来没有出口，员工只能关掉整个软件；先写终态再杀进程，否则会被判成"结果未知" |
| 上传了改名的假图片 | 落盘后用 Pillow 真解一次，失败就删文件返回 400；客户端不把 4xx 放进离线队列 | 只验扩展名等于给 images/ 开了个任意文件入口，备份还会忠实镜像这些垃圾 |
| 后台要离线可用 | 样式与图表全部本地实现，不引 CDN | NAS 内网可能不通外网 |
| 本地服务被网页调用 | sidecar 写请求校验 `Origin` 白名单（无 Origin 的本机程序放行） | CORS 只挡读响应，挡不住请求被 POST 执行 |
| 员工报障没日志 | sidecar/worker 日志落 `%APPDATA%\psluyong-lite\logs`（2MB×3 轮转），设置页一键复制诊断信息 | 打包后 stdout 被丢进 DEVNULL |
| 成品图命名 | 设置页可选 `作者.jpg` 或 `作者_标题.jpg`，同名自动加 `(2)` 序号 | 带时间戳的名字在文件夹里根本找不到人；但直接同名会覆盖，等于悄悄丢成品 |
| 审计 | 记录软删除、图片文件保留 | 误删可恢复（后台回收站一键恢复） |
| 后台写操作 | 会话 CSRF token（页面 meta + `X-CSRF-Token` 头） | 跨站表单冒用管理员会话；API Key 走自定义头，浏览器预检就拦掉了 |
| SQLite 并发写 | WAL + `busy_timeout=5000` + `synchronous=NORMAL` | 8 线程 waitress 下不设就是偶发 `database is locked`（data 在 NFS/SMB 上要改回 `DELETE`） |
| 操作可追溯 | `audit_logs` 表 + 后台「操作日志」页 | 容器日志会轮转，"这条谁删的"必须查得到 |
| 系统自身状态看不见 | 仪表盘底部条：最后备份 / 昨日日报推送 / 图片占用 | 业务指标再好看，备份挂了、日报没推也白搭 |
| 后台安全响应头 | `nosniff` / `X-Frame-Options` / `Referrer-Policy` / `Permissions-Policy` | 防点击劫持与 MIME 嗅探；CSP 待内联脚本全部外置后再上 |
| 登录被暴力猜 | 同来源 5 分钟内失败 5 次即 429 + 审计留痕 | 内网端口往往整层楼可达，不能裸奔 |
| 推送失败被当成成功 | 解析官方响应的 **`err_code`**，HTTP 200 但带错误码也算失败；4xx 与业务码不重试，只对网络异常/5xx 退避重试 | 群没开「机器人主动在群聊内发言」/ openid 失效 / 机器人被移出群时平台全回 200——只看状态码会让日志、徽标、仪表盘一起绿，而群里没有消息，兜底告警（判据就是 pushed 为假）也永远不触发 |
| 补传时把整批记录删了 | 只有 400/409/422 删；401/403/404 保留并标「受阻」，界面显示原因 | 换 API Key 忘同步时，旧实现给每条 401 都判「业务拒绝」→ 积压静默清空，界面还显示补传成功 |
| 登录一个真 QQ 号当机器人（NapCat） | **整条链路删除**，改用官方机器人：`QQBot {access_token}` 鉴权、token 提前 60 秒刷新、目标用 `group_openid` 而非群号 | 三个真实理由：① NapCat 的授权明确禁止未经许可的衍生分发，而它被打进安装包＝在分发；② 容器里存的是一个真号的登录态，6099 的 WebUI 就是那个号的操作台；③ 它顺带要一个匿名可达的回调端点来收群消息，那个端点泄露的是含员工姓名/稿件标题的报表。代价是群内「汇总」指令做不了——官方只投递 @机器人 的事件 |
| 日报漏推发现不了也补不回来 | 18:00 推快报 + 次日 08:30 巡检推「终版」（只在数据变了时发）+ 缺口告警；仪表盘按推送时点算「该推哪天」 | 18:00 之后补录的记录不落在任何一份日报里；APScheduler 的重启补跑对「进程重启」无效，漏了没人知道 |
| 同一天日报被推两遍 | 数据指纹（`stats_fingerprint`）比对已推送版本，一致就跳过；手动「重推」才 force | 服务重启重跑、重复部署、终版巡检都会让同一天看起来「该推一次」，群里出现两条一模一样的日报比没推更难解释 |
| 服务被开成两份，日报各推一遍 | 约束写进 [docs/DEPLOY.md](docs/DEPLOY.md) §3.4「必须单进程运行」；启动时在 `data/run/instance.lock` 取非阻塞文件锁，拿不到就打 `WARNING` + 仪表盘「后台服务」行转黄；**不阻止启动、不影响推送** | 「今天推过没有」是「读标记—发消息—写标记」三步、中间无锁，两个进程同时到 18:00 都会读到 `pushed=false` 而各发一遍（夜间备份/图片镜像同理）。抢锁选主能根治，但要跨平台文件锁 + 心跳 + 主挂接管，一台 NAS 一个容器没有对应收益，多一层零件就多一处会坏的地方——所以约束靠文档守，代码只负责让「有人多开了」别悄悄地发生。用文件锁而不是 pid 文件：容器里大家都是 1 号进程，跨容器看 pid 既看不到也不可信 |
| 客户端配置写坏就报废 | 原子写（tmp + `os.replace`）+ `config.json.bak` + 坏文件改名留档 + 逐字段校验 | 配置里存着服务器地址和 API Key；没有自动更新，写坏一次就只能逐台远程修。现在坏文件先留档、能回滚就回滚，一个字段类型不对也只影响它自己 |

## 部署

见 [docs/DEPLOY.md](docs/DEPLOY.md)：NAS Docker 部署、客户端打包、QQ 机器人配置、
回滚（镜像 git-sha tag / 数据库恢复彩排）、两份 Dockerfile 与 compose 的配置差异对照。

上线前跑一遍自检（DEPLOY 第四节的机器可判版，有 FAIL 即退出码 1，可直接进 CI）：

```bash
.venv/Scripts/python.exe scripts/preflight_check.py
.venv/Scripts/python.exe scripts/preflight_check.py --base-url http://127.0.0.1:8080   # 顺带探线上探针
.venv/Scripts/python.exe scripts/preflight_check.py --json                             # 给 CI 消费
```

三态输出：`通过` / `不通过`（退出码 1）/ `需人工`（机器判不了，比如 PS 版本、
备份恢复演练）。后一类会单独列成勾选清单，别把它当"不通过"，否则会养成"跑不过也照上"的习惯。

员工侧看 [docs/员工手册.md](docs/员工手册.md)（一页纸：先开 PS、四步出图、断网会怎样、
卡住查表、导诊断包找谁）。手册里的按钮名与屏幕文案由用例对着 Vue 源码校验，界面改名而手册没跟上会直接红。

NAS 部署包用 `scripts/package_nas.py` 打：

```bash
python scripts/package_nas.py              # 含本机 .env 的安装包
python scripts/package_nas.py --no-env     # 出厂包：不含密钥，目标机现填
python scripts/package_nas.py --no-data    # 空库部署
python scripts/package_nas.py --help       # 全部选项
```

**注意：默认打的 zip 含本机 `.env`（SECRET_KEY / API_KEY / ADMIN_PASSWORD 等密钥），属敏感件**——只在受控内网流转、勿外发、勿传网盘。发给其它机器/同事用 `--no-env` 出厂包（包内改为 `.env.example`，目标机 `cp .env.example .env` 后自建密钥）。

密钥一旦外流（截图、误提交进 git），必须轮换而不是只删提交——force-push 后旧提交的 blob 在
GitHub 上仍可按 SHA 直接下载。轮换用仓库自带脚本（会顺手重置数据库里的管理员密码，且拒绝把
备份写进仓库）：

```bash
python scripts/rotate_secrets.py --dry-run          # 先看计划
python scripts/rotate_secrets.py --backup-dir D:/psluyong-env-backups
```

换完还要同步每台员工客户端的 API Key；`QQ_BOT_SECRET` 只能去 q.qq.com 后台重置
（本地生成一个写进 `.env` 只会让机器人全部 401），见 [docs/DEPLOY.md](docs/DEPLOY.md) 第七节。

## 已知限制

- **PS 自动化仅 Windows**：非 Windows 环境 `core` 可 import 但不具备生成能力（已优雅降级，便于在 CI 里跑测试）。
- **PS 必须在本机运行**：方案是"调用员工机器上已打开的 PS"。若员工机器装不了 PS，需要改成集中生成服务器（架构改动）。
- **取消生成会在 PS 里留下文档**：worker 阻塞在 COM 调用里时收不到任何 Python 侧信号，取消只能杀进程，于是 runner 的 `finally: close_document` 跑不到。界面上会提示员工手动关掉那个未保存的模板文档。
- **sidecar 无鉴权**：只绑 `127.0.0.1` + CORS 白名单。本机其他程序仍可调用，单机桌面场景可接受，多用户共用电脑需要补 token。
- **SQLite 单写者**：小团队够用；将来并发上千再换 MySQL，届时 `models.py` 里的 `sqlite_where` 部分索引要换成对应语法。
